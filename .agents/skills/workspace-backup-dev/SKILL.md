适用于开发的每个项目。源码和自包含免安装分发包均存在时，无需重复请示，所有有关的有效文件一起上传，重点是完整源码、自包含免安装分发包、必要环境修改、修复脚本、补丁和有效临时修改。排除用户真实数据库、授权、Cookie、私钥和原始日志。

- 当前目标账户 https://github.com/alistrode。仓库内源码用 `git` / `gh` 推送；1.0 GB 运行包超过单文件 100 MB 上限，作为 GitHub Release 附件发布，不用 Git LFS。具体命令见 `.agents/skills/omnidispatch-delivery/SKILL.md`。
- AI 用过且对维护有用的命令、脚本必须随项目上传，并在项目 skill 中索引；必要的运行环境修改必须公开记录。
- 没有自包含分发包时，先请示是否全部上传。大版本可直接上传仓库；小版本须事先获准。用户本次明确的上传指令本身构成当前上传授权。
- 特别大且无意义的缓存、重复运行时、无关样例、调试垃圾、错误脚本和未被使用的内容可以排除。外置第三方项目、运行时、模型或可下载依赖必须随版本列出完整运行所需清单。
- 历史版本保留；新增交付要求不使历史包自动通过验收。

## 用户另行要求一键下载时

必须在当时完成云端单文件夹运行验收，不依赖未公开人工补丁；明确操作系统与架构。完整解压目录含应用、运行时、生产依赖和资源，按说明可直接启动。优先 GitHub；无项目分支则采用临时文件分支。备用 Filebin 为二进制正文 POST https://filebin.net/{唯一标识}/{文件名}，不是 multipart。保持原格式，小文件不额外打 ZIP。最终直链经重定向后必须 Content-Disposition: attachment，不得 inline 或要求点第二个按钮；实际下载并核对 SHA-256 后，完整 HTTPS URL 单独一行给出。不满足时不得冒充验收通过。
