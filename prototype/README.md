# OmniDispatch · 前端原型 v4

单文件：`index.html`。无构建、无依赖、无登录页、无侧边栏、无滚动。
`preview.png` 是渲染效果。核对一屏：`index.html#dbg`，左下角实时显示 `view / scroll / k`。

---

## 这一版改了什么

| 你指出的问题 | 现在的处理 |
| --- | --- |
| 中轴过于密集 | 中轴只剩一小段：从标题落到分叉点就结束了。**12 个来源不再挤在一条轴上** |
| 不够简洁 | 全页只有一棵树 + 标题。数字、版本、状态、口径全部收进树的节点与叶 |
| 圆圈没有信息 | 没有装饰性的空圈了。区域节点是**枝上的质点**：圆面积就是它的占比，旁边写百分比；来源节点是茎上的一个小点，不是空框 |
| 还有一个侧边栏 | 侧边栏删掉了。区域变成树的**第一级枝干**，不再是旁边的列表 |
| 枝叶没有阶次、是一块矩形 | 现在是四阶：主干 → 大枝（区域）→ 中枝（区域茎）→ 小枝（来源节点）→ 叶（渠道）。粗细逐级递减，底部参差不齐，不是方框 |

## 树的四阶

```
                      OMNIDISPATCH
                           │            ← 主干        3.0px
              ┌────────────┼────────────┐
           小红书          B 站         …            ← 大枝（弧线）1.1–2.2px，下垂
              ●            ●
              │            │                        ← 中枝（区域茎）1.0px
              ·            ·                          · 来源节点 3.4px
            ··●··        ··●··                      ← 小枝 0.65px
       social-auto-upload  biliup                     · 叶 = 渠道 3.6–4.4px
```

- **主干**从刊头垂到分叉点，先玫雾后蜜珀，两端淡出
- **大枝**六条下垂弧线，粗细随该区域占比变化
- **中枝**是每个区域的一条茎，来源节点依次排在茎上
- **小枝**从来源节点散到每一片叶
- **叶**就是渠道：一个点一片叶。灰点可达、玫瑰点降级、空心点不可达

茎在标签之间的空隙里才可见——看起来是从标签背后穿过去的，不压字。

## 每片叶都有内容

- 区域节点：圆点（面积 ∝ 占比）＋ 名字（字号 ∝ 占比）＋ 百分比
- 来源节点：名字（字号 ∝ 占比）＋ 渠道叶片 ＋ 首次出现时附 `22.8% · 3/4` 与 `v1.0.0-skills.2 · 10 天前`
- 同一来源在多个区域重复出现时，只保留名字与「坏掉的那条渠道」，不再重复数字
- 候选来源（虚线、浅色）：postiz / mixpost / postbot

## 两项占比

- **节点占比**：12 个来源，合计 100.0%；面积正比（直径 ∝ √占比）
- **区域占比**：6 个区域用独立口径算 `可用渠道×8 ＋ 在用来源×4 ＋ 近30天活跃×3 ＋ 待接入×2`，与节点占比互不推导；口径写在页脚
- **界面 0.5%**：挂在主干上的一个小点，`界面 0.5%`。树干就是界面本身，所以它占主干这点位置

## 一屏

启动时二分搜索缩放系数 k，同时受**高度**与**宽度**约束（最宽的一个来源标签必须装进它那一列），
所以既不会纵向溢出，也不会横向串列。807 / 907 / 1007 的可视高度都实测 `scrollHeight === innerHeight`。

## 落地

`apps/web/src/App.vue` 整体替换。数据接现有 `SOURCES` / `COVERAGE` / `engines.lock.json`，
`/api/channels` 供渠道可达性，`/api/updates` 供发版记录。`paint()` 负责按 k 重新计算并重绘整棵树，
在 Vue 里挂到 `onMounted` + `ResizeObserver` 即可。
